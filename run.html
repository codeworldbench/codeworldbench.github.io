Run it

From clone to leaderboard

Python 3.12. The agent CLI must already be on PATH — the benchmark launches it but does not install it.

Generated repositories execute untrusted model-written code with no container isolation. Run only in a disposable environment with no sensitive credentials.

  1. Install

    Set a scratch directory on a disk with room to spare; generation workspaces are large.

    # in the CodeWorldBench repository root
pip install -e .
export CWB_TMP_ROOT=/path/to/scratch

    CWB_ROOT, CWB_DATA_ROOT, and CWB_WORK_ROOT relocate config, dataset, and working state.

  2. Unpack the data

    The dataset ships as two archives under dataset/archives/: sources.tar.gz (the 118 environment workspaces) and eval_assets.tar.gz (case bundles and SWE baselines). Extract both at the repository root — each already contains its own top-level directory. 

    tar -xzf dataset/archives/sources.tar.gz       # -> sources/
tar -xzf dataset/archives/eval_assets.tar.gz  # -> eval_assets/

    Expect roughly 1.2 GB unpacked. To verify the archives first: cd dataset/archives && sha256sum -c SHA256SUMS. The extracted directories are gitignored, so unpacking in place leaves the working tree clean.

  3. Register a model

    printf '%s\n' "$YOUR_API_KEY" | cwb model \
  --mode api \
  --base-url https://your-endpoint/v1 \
  --api-key-stdin \
  --api-model YOUR_MODEL_NAME

    Use --mode api for hosted OpenAI-compatible providers, --mode vllm or --mode sglang for self-hosted ones. Repeat for every model. Credentials land in a gitignored directory. Refer to the model by its registered name from here on.

  4. Generate

    Install the pinned scaffold version first. Agent CLIs change their prompting and tool behavior between releases, so scores are only comparable at a fixed version — the reported Claude Code numbers use v2.1.251, and OpenAI models use Codex v0.154.0. 

    npm install -g @anthropic-ai/claude-code@2.1.251

cwb run --scaffolds cc --models YOUR_MODEL_NAME --max-concurrent-settings 24

    One model–scaffold pair over the full dataset schedules 236 tasks (118 environments × 2 settings). Add --continue to resume the latest run and retry failed work; narrow the scope with --env-id and --settings. 

    cwb status --models YOUR_MODEL_NAME   # progress
cwb stop   --models YOUR_MODEL_NAME   # stop a run

    Eight scaffolds ship in config/scaffolds/: cc (Claude Code, the default), openhands, opencode, qwencode-bailian, zcode-official, codex, kimi-code-cli, minimax-cli. Each is one TOML file plus an exec script; see CONTRIBUTING.md to add your own.

  5. Evaluate

    cwb eval --scaffolds cc --models YOUR_MODEL_NAME --settings GEN,SWE

    Each generated workspace is graded in place by one pytest process per setting against the canonical case bundle; the workspace database is restored afterwards. Settings run in parallel via --max-workers.

    Results land under eval/results/ as one file per setting plus a measurement.json summary, and only the requested scope is replaced. Leaderboards go to reports/ with per-domain and per-tier scores, GEN, P2P, F2P, and token totals. Every run records digests of the source tree, evaluation assets, and case set, so a score traces back to the exact inputs that produced it.

#Reading your scores

GEN and the category columns are macro-averages over environments; P2P and F2P are micro-averages over cases. Mixing the two aggregations produces numbers that look plausible and are not comparable to anything published here. The results page spells out both definitions.
