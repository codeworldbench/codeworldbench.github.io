Analysis

Every score is the end of a trajectory

A deduplicated archive of 1,619 trajectories lets us separate what the harness contributes from what the model does — and see which failures actually lie on the path to correctness.

#Difficulty rises with verified surface

Holding the scaffold fixed across the three GEN levels on the 50 common environments, macro-averaged pass rate drops 0.4580 (L1) → 0.4370 (L2) → 0.4069 (L3) while verified surface roughly doubles at each step. Four times the behavior costs about five points.

The decline comes from stateful coupling, not prompt length: higher levels demand sharing records, maintaining derived views, and coordinating side effects across calls. Crucially the failures are semantic rather than structural. Generated repositories pass structural setup but mismanage state transitions — stale counters, shallow success envelopes, inconsistent views — because agents build first, writing managers and registries before validating transition rules. More code does not help, and the strongest run writes less. Because all 50 environments score strictly between zero and one at every level, the slices work as diagnostics rather than difficulty gates.

#The scaffold shapes behavior more than the model

Holding two models fixed and varying the harness across all 118 environments. Because scaffolds define turns differently, interaction is measured in tool calls.

Tool mix is a property of the harness

Under Claude Code both models spend 54–68% of GEN calls in shell versus 2–4% on edits, an edit-to-execution ratio around 0.05. Qwen Code inverts this to 1.63 and 1.71, with OpenHands in between. Leaderboards that mix scaffolds partly benchmark harnesses.

Volume varies at fixed capability

Mean GEN calls per run span 93.3–174.2, a 1.9× variance driven solely by the harness, with individual runs hitting 500 calls. SWE requires more interaction than GEN in four of six setups (ratio ≈ 1.4); the exceptions are reading-heavy Qwen Code runs that prepay comprehension costs.

Errors move to the tool interface

Under Claude Code, assertion failures in self-written probe scripts account for about 60% of errors. Under OpenHands and Qwen Code, interface friction — tool misuse, missing paths — dominates. Absolute error rates stay within 2.1–7.0%. Internal code failures lie on the path to semantic correctness; tool misuse merely pads trace length.

#How agents spend their turns

600 traces from six families across the 50 common environments in GEN L3 and SWE: two closed-source models and four open-source ones. Actions are normalized to operations and harness results to outcomes, so Codex and Claude Code are comparable. Claude Opus 5 shares the open-source harness, which isolates model effects from harness effects.

Closed-source models act on the world; open-source models read about it

On GEN L3, closed-source models spend 86% of operations on execution, 11% on edits, 2% on reads; open-source models spend 23% reading and 5% editing. Claude Opus 5 reads files in under 6% of operations while Kimi K3 spends 36.5% of GEN reading, with a 3.45-point gap in common GEN. One verifies by executing, the other by inspecting. Under SWE, edit share rises to 7.3–14.5% as targeted modification replaces probing.

Repair costs more, and no one buys accuracy with turns

Claude Opus 5 finishes GEN in 66.8 operations; Qwen3.8-27B needs 139.2 for a lower score. SWE carries a repair surcharge of 1.1–1.6× in operations and cost ($5.64–$12.60 GEN vs. $8.20–$18.77 SWE) — maintaining invariants means reverse-engineering them first. In six of eight Claude Code cells the top volume quartile scores below the bottom quartile, by up to 12.0 points on GEN and 9.7 on F2P. Long traces signal struggle, not thoroughness.

Only one model habitually runs a real test suite

GPT-6 Astra runs test suites in 70% of GEN and 96% of SWE runs. Other models do so in only 2.2% of runs, and never for Claude Opus 5 or GLM-5.3 on GEN. Ad-hoc scripts verify a single run and leave no reusable artifact, so they miss exactly the regressions that matter: an action returns success while writing invalid state.

The two groups fail at different layers

Open-source failures come mainly from self-written code (80% GEN, 73% SWE, against 10% and 14% interface errors). For closed-source models under SWE, interface issues rise to 43% while own-code errors fall to 24%, with GPT-6 Astra timing out on 25% of failed SWE calls due to full test runs. Failures stay shallow — 2.6–9.2% of outcomes, streaks averaging 1.0–2.7 calls — and correlate weakly with score: agents fail smoothly rather than catastrophically.

#Does construction quality reach a downstream agent?

Generated environments serve as substrates for downstream training and evaluation, which makes construction quality the thing that propagates. 387 reference-authored tasks across the 36 common GEN environments successfully built by three generators under OpenCode. Qwen3.8-27B solves all of them through smolagents at temperature 0 with at most 30 tool calls, under seven conditions: the reference environment, plus each generated environment with and without a GLM-5.3-Flash-authored skill document.

Construction quality governs downstream transfer

The reference environment reaches 49.6% grounded pass; generated environments retain only one-eighth to one-half of that (24.8, 18.1, 6.2) — roughly 12% to 50% of the reference success rate, mirroring their construction scores. Reference failures come almost entirely from task difficulty — every required tool exists. Generated environments add defects that were never the task's fault: missing tools cause up to 33% of task failures and 27.7% of call invocations in the weakest generator, which omits 332 tools and invents 203 of roughly 1,250 reference tools.

Skills buy efficiency, not completion

A skill document raises call success and roughly halves budget exhaustion, but pass-rate gains stay at or below 1.3 points. High-quality environments benefit disproportionately — a 9× larger call-success gain than the bottom tercile. Documentation mitigates overhead; it cannot recover omitted tools. The environment sets the ceiling, and skills decide how closely agents reach it.

#Where this points

Three targets follow from where the failures land, none of them requiring a change to the underlying model.

Supervise state rather than output

Return-value checks cannot express what these failures look like. Grading has to reach the state an action induces.

Require self-verification before submission

Agents already commit large execution budgets to iterative file manipulation. Scaffolds that systematically exercise tool interfaces and verify persistent state can channel that effort into early verification.

Treat shared invariants as an artifact

Commit once to identifier policies, validation order, and derived-view update rules, then implement each tool against that definition instead of re-deriving it per tool.

#Conclusion

By verifying persistent state alongside tool return values, CodeWorldBench exposes semantic errors that standard code benchmarks overlook. Frontier agents reliably preserve existing behavior, but struggle to synthesize correct state transitions from scratch or repair semantic defects. Those defects propagate: agents operating inside generated environments suffer performance drops from crashing, inconsistent, or missing tools. Building stateful environments is an unsolved challenge, and closing it calls for coding agents with rigorous state reasoning and automated self-verification.
